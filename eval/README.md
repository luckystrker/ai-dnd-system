# Eval-набор DM-бота

Синтетические сценарии для регрессионного гейта. Реальных трасс нет: кейсы
собраны из правил `internal/dm/instructions.md` и истории `fix:`-коммитов
TS-бота. Набор одинаково читается загрузчиком (`evalgame.LoadSuite`) и
исполняется живым раннером (`internal/evalrun`).

## Формат

`eval/cases/*.jsonl`, одна JSON-строка — один кейс:

```json
{"name":"memory-01-damage-on-player-turn","category":"memory","speaker":"Дэн","role":"player","input":"Дэн: Меня снова ранили — минус 4 хита. Иду дальше.","scorers":[{"name":"tools_called","params":{"names":["combat"]}},{"name":"tool_ok","params":{"tool":"combat","args":{"action":"damage"}}},{"name":"judge","params":{"rubric":"…"}}]}
```

- `name` — уникальное имя кейса (префикс = категория);
- `category` — `agency`, `rolls`, `checks`, `combat`, `memory`, `day`,
  `neutrality`, `group`;
- `speaker` и `role` (`player` | `dm`) — кто пишет и с какими правами;
  `speaker` обязан встречаться в `input`. Раннер собирает по ним фикстуру:
  кампанию, партию (Дэн/Лиса), привязку чата и сессию говорящего. Баг
  групповой записи воспроизводится только на `role: "player"`;
- `input` — сообщение(я) игроков, как их склеивает групповой чат;
- `scorers` — список скореров: строка-имя или `{"name":…,"params":{…}}`;
- `postconditions` — проверки БД **после** хода (исполняются раннером):
  `{"type":"day_summary","day":"closed","fields":["summary","headline"],"expect":"nonempty"}`.
  Для закрытого дня проверяются саммари и шапка; очередь летописца
  доигрывается после хода, поэтому кейс day-01/02 проверяет и её;
- `fault` — подмена результата тула ошибкой на N-м вызове:
  `{"tool":"skill_check","call":1,"error":"unknown skill: Восприятие"}`;
  `tool` обязан быть реальным тулом набора. Реализует middleware раннера;
- `skip_until` — слайс, до которого кейс не считается в наборе, строго
  `slice-N` (`checks-05-tool-error-retry` ждёт fault, слайс 7). Загрузчик
  отдаёт `ActiveAt(slice)`; `cmd/eval` по умолчанию исполняет слайс 7.

Неизвестные поля и параметры — ошибка загрузки (опечатка не проглатывается).

## Скореры

Механические (работают офлайн, без модели):

| имя | что проверяет |
|---|---|
| `tools_called` | вызваны все перечисленные тулы (ago; `mode: "any"` — любой из) |
| `tools_not_called` | ни один из запрещённых тулов не вызван |
| `tool_args` | аргументы вызова — подмножество ожидаемого JSON (`"*"` — любой скаляр, `contains` — подстрока, `match: "all"` — каждый вызов) |
| `tool_ok` | совпавший вызов реально отработал: без `Err`; JSON-результат — не `ok:false` и без непустого `error`, plain-строка — без точных фраз отказа авторизации |
| `tool_sequence` | имена тулов встретились в указанном порядке |
| `no_tool_calls` | в трассе нет ни одного вызова тула |
| `quotes_roll` | числа из результата `skill_check`/`roll_dice`/`combat` подтверждены одной из форм ответа (`d20 = 7`, `выпало 7`, `итог 10`, `= 10`, `DC 15`); выдуманное число вместо ожидаемого — fail |
| `answer_omits` | в ответе нет запрещённых штампов (регистронезависимо) |

Смысловые (нужен LLM-клиент, только живой прогон):

| имя | что проверяет |
|---|---|
| `judge` | LLM-судья по рубрике `params.rubric`; видит финальный ответ **и** вызовы тулов, возвращает `{"score":0..1,"reason":…}`, порог 0.5 |

Модель судьи — `muse-spark-1.3-contributor` через OpenCode Go (Responses API,
тот же ключ, что у бота); переопределяется `EVAL_JUDGE_MODEL` и
`EVAL_JUDGE_PROVIDER`, клиент собирает `evalgame.NewJudgeClient(os.Getenv)`.
Без ключа живой прогон падает сразу с понятной ошибкой.

## Живой прогон

```bash
go run ./cmd/eval -n 1 -out eval-results/last.json
go run ./cmd/eval -case rolls-05-narrate-per-tool-output -n 5
go run ./cmd/eval -baseline eval-results/baseline.json -gate
```

- Раннер (`internal/evalrun`) на каждый повтор поднимает временную SQLite,
  собирает кампанию/партию/привязку/сессию и настоящий DM-агент с настоящими
  тулами. В фикстуре уже идёт бой и записано его начало: кейсы про урон
  проверяют запись, а не догадку модели о бое.
- `postconditions` входят в вердикт кейса: без `advance_day` день не закрыт —
  кейс провален.
- `fault` — middleware подменяет результат тула `ToolErrorEvent` на N-м
  вызове в ходе; тул при этом не выполняется.
- Случайность детерминирована: `0.5` даёт d20 = 11. `rolls-05` идёт дважды —
  `/nat-20` и `/nat-1`, чтобы проверить пересказ успеха и провала.
- `-n K` — повторы; на кейс считаются Pass@k (хотя бы один) и Pass^k (все).
  Pass rate отчёта — по кейсам (все повторы), `run.pass_rate` — по первым
  повторам (для `eval.Diff`).
- Отчёт: `evalgame.Report` в JSON (кейсы, повторы, категории, токены) плюс
  вложенный `run` — совместимый `eval.RunResult`.

## Гейт

Baseline на eve снять нельзя (TS-бот локально не собирается), поэтому гейт
абсолютный и включается флагом `-gate`:

- `-min-pass 0.75` — общий pass rate;
- `-category agency=0.7,memory=0.8,...` — пороги категорий;
- `-required case1,case2` — обязательные кейсы. По умолчанию берутся четыре
  поведения: агентность (`agency-03-group-help-wait`), групповая запись в
  память (`memory-01-damage-on-player-turn`), закрытие дня
  (`day-01-overnight-rest`), публичные броски (`rolls-01-skill-check-public`).

Значения по умолчанию — `evalgame.DefaultGate()` (утверждены владельцем,
PLAN 30) и переопределяются флагами. Регрессионный гейт: `-baseline <json>`
падает на кейсах, которые проходили раньше и провалились сейчас (через
`eval.Diff`).

## Калибровка судьи

`eval/judge/calibration.jsonl` — 4 заведомо хороших и 4 плохих ответа DM с
рубриками. Живой прогон оценивает их судьёй: good обязан пройти, bad —
провалиться; иначе процесс завершается ошибкой. Офлайн обвязка проверяется
`TestCalibrateSeparatesGoodAndBad` с подменным судьёй.

## Калибровка Telegram

`go run ./cmd/eval -telegram` — офлайн-симуляция последовательностей сообщений
(окно склейки 2.5 с, follow-up 10 мин): сколько ходов LLM будится и сколько
батчей подавляется. Значения не меняются, отчёт — данные для владельца.
