# Миграция с eve (TypeScript) на ago (Go)

Цель: бот целиком переписан на Go поверх фреймворка
[ago](https://github.com/luckystrker/ago). Схема `data/campaigns.db`
сохраняется — Go-версия открывает ту же базу без миграции данных. TS-код и
eve удаляются перед мержем ветки `ago-port` в `main`, после того как eval-набор
на Go проходит без регрессий.

## Решения (зафиксированы 2026-11-02)

1. **Полный порт**, не 1:1: вместе с портом исправляется harness (ниже).
2. **Баги из прожарки чинятся только в Go-версии**, TS не трогаем:
   - запись в память в группе: тулы записи требуют роль `dm` у автора
     текущего сообщения (`access.ts` → `resolveCampaignForWrite`), поэтому на
     ходах обычных игроков HP/лут/NPC не сохраняются;
   - летописец без identity доверяет любому `campaignSlug` из аргументов модели.
3. **«Добрый» d20 остаётся как есть** (`makeLuckyRandom`, история на сессию).
4. **История сессий eve не переносится.** Память кампаний (БД) — переносится.
5. **Модель** `deepseek-v4.1-flash`, провайдер на выбор: OpenRouter,
   OpenCode Go, нативный ключ DeepSeek (все — OpenAI-совместимый Chat
   Completions через `openai.NewOpenAICompletions` + `BaseURL`).
6. **Runware-иллюстрации** переносятся.
7. **Деплой**: VPS, long-poll, один Go-бинарь под systemd (вместо tmux + eve).
8. **Eval-набор синтетический** (реальных трасс нет): сценарии из правил
   `instructions.md` и истории `fix:`-коммитов.

## Решения владельца после ревью слайсов 0–1 (2026-11-02)

9. **id модели DeepSeek** утверждён: у нативного DeepSeek — `deepseek-flash`
   (его обслуживает DeepSeek-V4.1-Flash-1017), у OpenRouter и OpenCode Go —
   `deepseek-v4.1-flash`.
10. **`MAX_TOOL_ROUNDS=12`** по умолчанию утверждён как стартовое значение;
    уточняется после замеров на живом прогоне.
11. **Провайдер по умолчанию — OpenCode Go** (`LLM_PROVIDER=opencode-go`).
12. **Модель судьи eval — `muse-spark-1.3-contributor` через OpenCode Go**:
    тот же провайдер и ключ, что у бота; модель обслуживается Responses API
    (`https://opencode.ai/inference/go/openai/v1/responses`), поэтому судья
    собирается через `openai.NewOpenAIResponses`. Провайдер и модель
    переопределяются `EVAL_JUDGE_PROVIDER` / `EVAL_JUDGE_MODEL`; без ключа
    живой прогон с судьёй падает сразу с понятной ошибкой, офлайн-тесты
    ключа не требуют.
13. **`ErrMaxToolRounds`**: игрокам — короткий нейтральный ответ
    («DM задумался, повтори ход»), без диагностики; трасса уходит в лог,
    записанное тулами не откатывается. Реализация — слайс 5.

## Редизайн harness (входит в порт)

| Было (eve) | Стало (ago) | Закрывает |
|---|---|---|
| «после `advance_day` всегда вызови chronicler» — правило промпта + страховочный хук | `advance_day` в коде ставит задачу летописцу (детерминированный шаг) | дни без саммари |
| HP в `gameState.party`, `combat.order` и листе SQLite; синхронизирует LLM | один источник истины — SQLite; `combat` сам пишет HP; `gameState` удалён | расхождение HP |
| каждое сообщение группы = полный ход LLM | склейка сообщений чата за окно N сек в один ход (`run.Enqueue`) + дешёвый гейт «отвечать ли» | стоимость, перехват разговора игроков |
| `ok` до обработки, нет дедупа, rate-limit выкидывает сообщения | durable inbox в SQLite с дедупом по `update_id`; превышение лимита пишется в транскрипт, но не будит LLM | потеря сообщений |
| окно 256k–900k токенов, растёт с длиной кампании | фиксированное окно ~64–128k, `compact.New(TokenTrigger)`; блок памяти — в хвосте контекста (policy), не в системном промпте | стоимость, кэш префикса |
| ошибки тулов — свободный текст / `{ok:false}` | типизированная ошибка: `code`, `retryable`, `remediation` | слепые повторы |
| лимита шагов нет (`sessionTimeoutMs: false`) | `WithMaxToolRounds`, дедлайн хода, бюджет токенов (`observers.TokenMonitor`) | циклы и расход |
| 25 файлов-копий тулов у летописца | одна Go-функция, два toolkit-а (DM / chronicler) | расхождение копий |
| летописец сам рапортует счётчики | счётчики считаются по изменениям в БД | непроверяемый отчёт |
| поведение проверяют живые игроки | `ago/eval` + регрессионный гейт в CI | регрессии промпта |

Авторизация: различаем «человек просит» и «действует DM-агент». Право на
запись в память кампании даёт **привязка сессии к чату кампании** (вычисляется
кодом), а не роль автора сообщения. Роль `dm` нужна только для
административных команд (`/startcampaign`, `/endcampaign`, `/invite`).
Slug кампании попадает в тулы через DI (`aginject`), а не из аргументов модели.

## Чего нет в ago — пишем сами

- **Telegram-канал**: long-poll (`getUpdates`), `sendMessage` с HTML и
  фолбэком на plain, `sendChatAction`, `sendPhoto`, загрузка файлов, `/join`,
  разбивка длинных сообщений, топики форума (`is_topic_message`).
- **`stream.Storage` на SQLite** (durable-история ходов + `Resume`); в ago есть
  только in-memory и Redis.
- **Драйвер SQLite**: `modernc.org/sqlite` (pure Go, FTS5 есть) — внешняя
  зависимость приложения; к ядру ago это правило не относится.
- `WithMaxToolRounds` в ago по умолчанию без ограничения — задаём явно.
- contrib-модули ago без тегов и с `replace ../..` — не используем.

## Слайсы (каждый — тесты зелёные, отдельный коммит)

0. **Каркас**: `go.mod`, `cmd/bot`, конфиг из env, выбор провайдера,
   CI (`go vet`, `go test`, сборка) рядом с текущим npm-CI.
1. **Eval-набор**: 30–50 синтетических сценариев в JSONL — агентность (не
   говорить за PC), публичные броски, `skill_check` vs `roll_dice`, бой по
   инициативе, групповая запись в память, закрытие дня, нейтральность.
   Скореры: mechanical (`ToolsCalled`, вызовы/аргументы) + LLM-judge по
   рубрике. Прогон на TS-боте — baseline (нужен ключ LLM).
2. **Движок**: порт `dnd5e.ts`, `combat.ts`, `rewards.ts` + их тесты.
3. **Хранилище**: порт `store-sqlite`, journal, npc, locations, factions,
   world-state, ledger, combat-snapshot, FTS5-поиск — на той же схеме;
   тест открытия копии существующей БД.
4. **Тулы**: 42 тула с типизированными ошибками и новой авторизацией;
   toolkit-ы DM и chronicler.
5. **Агенты**: DM (`instructions.md` через `embed`), chronicler, skills
   (`create-campaign`, `create-character`), policy блока памяти, compaction,
   лимиты, детерминированное закрытие дня.
6. **Telegram-канал**: inbox, очередь чата, склейка, гейт, форматирование,
   Runware, `stream.Storage` на SQLite.
7. **Гейт**: eval на Go ≥ baseline, e2e-скрипты, деплой (systemd unit,
   backup), README/AGENTS.md на Go.
8. **Удаление TS/eve**, мерж в `main`.

## Открытые вопросы

- Окно склейки сообщений (N сек) и критерий гейта «отвечать ли» —
  калибруются eval-сценариями группового чата.

Закрыто решениями владельца 2026-11-02: base URL и id моделей провайдеров
(сверены с документацией, решения 9 и 11), лимит раундов тулов (10), модель
судьи eval (12), поведение при `ErrMaxToolRounds` (13).
