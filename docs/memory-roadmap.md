# Roadmap: новые типы памяти

> **Статус: не реализовано.** Этот документ фиксирует, какие типы памяти нужно
> добавить в будущем отдельными итерациями. Каждый пункт — самостоятельная
> работа со своим скоупом (модель данных + хранилище + точка интеграции в
> контекст хода и/или тул). Зафиксировано по итогам аудита системы памяти,
> чтобы будущая реализация опиралась на готовые требования и дизайн, а не
> начиналась с нуля.

Текущая система памяти (после базовых улучшений) покрывает: транскрипты дней,
саммари/заголовки дней, хронику кампании, ключевые события (вкл. «вечные»),
NPC-карточки с памятью, квесты, открытые нити, состояние партии и автосохранение
боя. Ниже — пробелы, которые требуют **новых сущностей**, а не доработки
существующих.

---

## C1. Карта / локации

**Проблема.** `location` сейчас — свободная строка у персонажа. Нет связей
между местами, нет понятия «обнаружено / посещено», мир «плоский»: бот не может
сказать, как добраться из Морага в Чёрный Лес и через что придётся пройти.

**Предлагаемая сущность.**
```
Location {
  id, campaignId, name, slug
  description?            // что видно/известно
  connections: [{ to: locationId, via?, discoveredDay? }]
  discoveredDay           // когда впервые нашли
  visitedDays: number[]   // дни, когда партия там была
  current?                // true, если партия там сейчас
}
```

**Хранение.** Вариант A (следуя паттерну NPC): MD-файлы
`data/campaigns/<slug>/locations/<slug>.md` (frontmatter = профиль, тело =
описание/заметки) — `agent/lib/campaigns/locations.ts`, всегда-MD. Вариант B:
SQLite `locations` + `location_connections` (если нужен графовый обход).

**Интеграция.** Секция «Карта» в авто-блоке памяти
(`agent/instructions/campaign-context.ts`): текущая локация + известные связи.
Тулы: `upsert_location`, `move_party` (ставит `current`, добавляет день в
`visitedDays`, пишет в транскрипт), `list_locations`.

## C2. Игровое время / окружение

**Проблема.** Есть только `currentDay` (целое число). Нет времени суток, даты в
мире, погоды, фаз луны. Нет атмосферности и нет механических влияний: ночь не
даёт скрытых бросков, шторм — помехи на проверки.

**Предлагаемая структура.** Поля на `Campaign` (`agent/lib/campaigns/types.ts`):
`timeOfDay` (утро/день/вечер/ночь), `inGameDate` (строка по календарю мира),
`weather?`. Или отдельный `world-state.md` в папке кампании, если атрибутов
много и они часто меняются.

**Интеграция.** В авто-блоке памяти — строка «Игровое время: вечер, 3 день
Месяца Туманов; пасмурно». Тулы: `advance_time` (двигает `timeOfDay`, при
переходе через полночь предлагает `advance_day`), `set_weather`. Механику
(помехи ночью) добавить в `skill_check`/`combat` как опциональный модификатор.

---

## C3. Лут / экономика

**Проблема.** `gold` — число у персонажа; истории нет. Нельзя追溯 «откуда у
нас этот меч» или «на что мы потратили 50 золотых в день 3». Экономика
непрозрачна.

**Предлагаемая структура.** Append-only журнал в
`data/campaigns/<slug>/history/ledger.md` (по паттерну key-events):
```
{ day, type: found | spent, itemOrGold, by?, note? }
```
Строка: `- [День 3] найдено: серебряный кинжал (Дэн); пояснение…`.

**Интеграция.** Журнал не грузится в авто-блок целиком (растёт); доступ через
`search_memory` (уже есть keyword-поиск) и новый тул `list_ledger`
(опционально, с фильтром по дню/типу). Авто-запись: при вызове `grant_character`
(выдача золота/предметов) дописывать строку в ledger из самого тула —
детерминированно, без отдельного вызова.

## C4. Фракции / отношения NPC↔NPC / репутация

**Проблема.** Отношения сейчас только NPC→PC (`attitude` в карточке NPC).
Фракций нет, отношений между NPC нет. Политические сюжеты (два клана враждуют,
репутация у гильдии) невозможны — мир не моделируется.

**Предлагаемая структура.** Расширить `NpcProfile.relationships` до
произвольных целей (NPC или фракция), не только персонажей. Новая сущность
`Faction { id, name, description, standing: number }` (репутация партии).
Хранение: SQLite `factions` / `faction_standing` (структурированные данные) или
MD `data/campaigns/<slug>/factions/<slug>.md`.

**Интеграция.** В авто-блоке — короткий список фракций с текущим standing.
Тулы: `upsert_faction`, `adjust_standing`. Связь с квестами: квестодатель может
быть фракцией; `complete_quest` корректирует standing.

---

## C5. Состояние мира / последствия

**Проблема.** `key-events.md` — это журнал моментов (append-only), а не живое
текущее состояние мира. «Кто сейчас мёртв», «какой город сожжён», «какие
решения приняты» — всё это размазано по саммари и key-events. Мир не реагирует
на прошлые решения последовательно: бот может «оживить» убитого NPC.

**Предлагаемая структура.** Перезаписываемый (не журнал!)
`data/campaigns/<slug>/history/world-state.md` с актуальными фактами мира:
```
## Погибшие
- Ян (день 1) — найден у ручья
## Изменения
- Деревня Мораг: на persuade (день 2) — староста благодарен
```

**Интеграция.** Грузится в авто-блок памяти целиком (компактно, с капом).
Тулы: `record_world_change` (upsert по категории), `list_world_state`. Связь с
NPC: при смене статуса NPC на `dead` авто-дублировать в «Погибшие». Chronicler
обновляет при закрытии дня.

## Приоритизация (предложение)

- **C2 (время/окружение)** — самый простой вход, мало данных, заметная
  атмосферная польза.
- **C1 (карта)** — средняя сложность, высокая ценность для исследования.
- **C3 (лут)** — низкая сложность, в основном авто-лог в `grant_character`.
- **C5 (состояние мира)** — средняя сложность, решает конкретный класс багов
  («оживление» мёртвых).
- **C4 (фракции)** — самая сложная, нужна только когда появятся политические
  сюжеты.

## Общие принципы для всех пунктов

- Соблюдать существующий split: структурированные данные → SQLite, нарратив →
  MD-файлы в папке кампании (см. обновлённый `AGENTS.md`).
- Новые секции добавлять в `buildMemoryBlock` (`campaign-context.ts`) с
  разумными капами; растущие журналы не грузить целиком — через `search_memory`.
- Chronicler должен обновлять новые типы памяти при закрытии дня.
- Тесты на темп-папках (`test/helpers.ts`), без `.env`/БД.
