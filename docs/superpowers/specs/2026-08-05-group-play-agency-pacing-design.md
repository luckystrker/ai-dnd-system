# Групповая игра: агентность DM, темп игры и авто-вступление

Дата: 2026-08-05
Статус: утверждено пользователем

## Проблемы

1. **DM играет за игроков.** В групповой игре агент часто принимает решения,
   говорит и действует за чужих персонажей.
2. **Бот сразу пушит действие дальше.** Любой реплай боту запускает полный ход
   DM, который продолжает сцену, не давая другим игрокам повзаимодействовать.
3. Запрошена команда `/inviteAll`; по итогам обсуждения заменена на
   **полную авто-регистрацию** всех, кто пишет в привязанном чате.

## Корневые причины

- Поведенческая: в `instructions.md` агентность игроков ограничена одной
  мягкой строкой; в инъектируемом контексте партии нет связи
  персонаж → владелец, «текущий говорящий» неявный.
- Архитектурная: каждое сообщение-реплай запускает ход DM; механизма «подождать
  остальных» нет. Сообщения игроков не в адрес бота канал вообще отбрасывает
  (`shouldDispatch`), поэтому DM не видит диалоги между игроками.

## Решение

### 1. Агентность (A1 + A2)

**`agent/instructions.md`** — новая секция `## Agency`:

- DM управляет только миром и NPC. Запрещено писать действия, реплики, мысли
  и решения за персонажей игроков.
- Если действие игрока затрагивает другого PC («идём вместе», «он мне
  помогает») — обратиться к этому игроку по имени и ждать его ответа.
- Каждый ответ завершать на точке решения вопросом — действующему игроку или
  всей партии.

**`agent/instructions/campaign-context.ts`** — контекст с владельцами:

- Блок «Партия»: для каждого персонажа добавляется владелец через join
  `CharacterSheet.ownerUserId` ↔ `CampaignMember.userId`:
  `- Розалин (маг, ур. 2; играет @username)`. Если владельца нет в members —
  без приписки.
- Новая строка в начале блока: `Сейчас пишет: @username` (из
  `resolveCallerIdentity`) и, если у говорящего есть персонаж, —
  `персонаж: Розалин (управляет только им)`. Для остальных PC —
  `остальные персонажи партии: ... — не пиши и не решай за них`.
- Строка добавляется только для групповых чатов (`chat_type != private`).

### 2. Темп игры (B1 + чтение всех сообщений группы)

**`agent/instructions.md`** — правила темпа в секции `## Formats`/`## Rules`:

- В групповом режиме останавливаться на точках решения и собирать решения
  партии; не разрешать групповую сцену по сообщению одного игрока.
- Диалоги игроков между собой видны в инъектируемом транскрипте дня —
  учитывать их при наррации, но не прерывать: давать игрокам договорить.

**`agent/channels/telegram.ts`** — наблюдение за всем трафиком группы:

- Для группового сообщения в чате/топике, привязанном к кампании, которое НЕ
  проходит `shouldDispatch` (не реплай боту, не команда, не @упоминание):
  1. записать его в транскрипт текущего дня через `appendTranscriptEntry`
     (`kind: "player"`, автор — username ?? имя ?? userId, маркер дедупликации
     `evt:tg-<chatId>-<messageId>`);
  2. авто-регистрировать автора (см. раздел 3).
  Ход агента НЕ запускается — бот молчит, пока игроки общаются между собой.
- Для сообщений, проходящих `shouldDispatch` в привязанном чате, —
  авто-регистрация автора перед `send()` (текущая логика диспетчеризации
  не меняется).
- Поиск кампании для этого пути — без фильтра по статусу (см. раздел 3).
- Записи автоматически попадают в инъектируемый блок «Текущий день»
  (`readDayTail`, 30 последних строк) — изменений инъекции не требуется.
- **Требование к деплою**: бот должен получать все сообщения группы —
  privacy mode выключен в BotFather (`/setprivacy → Disable`) либо бот
  является админом группы. Зафиксировать в `README.md` и комментарии в
  `.env.example`.

### 3. Авто-регистрация вместо /inviteAll (C2)

- **`agent/lib/campaigns/store.ts`**:
  - новый метод интерфейса `autoRegister(campaignId, user: NewMemberInput): Campaign`:
    добавляет автора как `player` БЕЗ проверки роли DM; идемпотентен —
    если участник уже есть, ничего не делает; при достижении `MAX_PARTY` (6)
    молча пропускает (не бросает ошибку). Роль `dm` этим путём назначить
    нельзя.
  - новый вариант поиска `findByBoundChat(chatId, messageThreadId, options?: { anyStatus?: boolean })`:
    с `anyStatus: true` не фильтрует по `status === "active"` — авто-регистрация
    и запись транскрипта работают в любой момент жизни кампании (у setup-кампаний
    boundChat всё равно отсутствует, поэтому они находятся только после привязки).
    Существующие вызовы (контекстное окно, game context) остаются на фильтре
    по active.
- Команда `/inviteAll` **не вводится**: любой написавший в привязанный чат
  мгновенно становится участником и может создавать персонажей. `/invite`
  сохраняется — пригласить человека до его первого сообщения можно только им.

### 4. Тесты и документация

- `scripts/smoke-campaigns.ts`:
  - `autoRegister`: добавление, идемпотентность, пропуск при полной партии,
    невозможность назначить dm;
  - `findByBoundChat(..., { anyStatus: true })` находит finished-кампанию.
- Ручной e2e-чеклист (группа, 2 игрока):
  - игроки переписываются без реплая боту → записи появляются в
    `history/days/day-NNNN.md`, бот молчит;
  - следующий реплай боту → DM учитывает диалог и не действует за второго
    игрока;
  - новый участник пишет в чат → появляется в `members` в `campaign.md`.
- `README.md`: секция про privacy mode; `agent/instructions.md` — пометка,
  что игроки вступают в кампанию автоматически.

## Риски

- Privacy mode включён → бот физически не видит «чужие» сообщения; лечится
  только настройкой BotFather/админством (задокументировано).
- Файл дня растёт от внутреигрового общения — ограничено существующим
  `DAY_TAIL_LINES = 30` при инъекции и summarize от chronicler.
- Поведенческие правки (A1/B1) вероятностны; если DM продолжит играть за
  игроков — следующий шаг: hard-guardrail хук (вариант A3), намеренно
  отложен.
