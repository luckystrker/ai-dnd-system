# Scene Illustrations via Runware

Дата: 2026-08-05
Статус: approved

## Цель

Когда в рамках кампании генерируется значимая сцена, игроки должны получать
её иллюстрацию с описанием сцены. Генерация изображений выполняется через
Runware API (REST). Функция работает **только внутри кампании**, привязанной
к чату/топику Telegram; вне кампании генерация не запускается.

## Принятые решения (из брейншторма)

- Триггер: инструмент DM-агента `illustrate_scene`; DM сам решает, когда
  началась значимая сцена. Дополнительно: у персонажей при создании
  фиксируется описание внешности для консистентной генерации.
- Доставка: фото отправляется в чат/топик, привязанный к кампании.
- Промпт: описание сцены от DM + автоматический контекст (сеттинг кампании,
  внешность персонажей в кадре), детерминированная сборка без LLM.
- Параметры: модель и размер через env с дефолтом (SDXL, 1024×1024).
- Ошибки: тихий фолбэк на текст — игра не блокируется, уведомлений нет.
- Таймаут запроса к Runware: 30 секунд.

## Архитектура

Один новый eve-tool `agent/tools/illustrate_scene.ts` и один новый модуль
`agent/lib/runware.ts` (клиент Runware). Никаких изменений в Telegram-канале
не требуется: фото отправляется прямым вызовом Bot API `sendPhoto` по
`boundChat` кампании.

### Поток

1. DM вызывает `illustrate_scene({ sceneDescription, characters? })`.
2. Тул резолвит кампанию по auth текущего чата (`resolveCampaign` из
   `agent/lib/campaigns/access.ts`). Кампании нет или она не привязана к
   чату → мягкая ошибка, генерации нет.
3. Тул собирает промпт (см. ниже).
4. Тул вызывает Runware REST API и получает `imageURL`.
5. Тул отправляет фото в `campaign.boundChat` (с `message_thread_id` для
   форум-топиков) с caption = `sceneDescription`.
6. Тул возвращает `{ ok, imageUrl }` либо мягкую ошибку; DM продолжает
   нарратив независимо от результата.

## Тул `illustrate_scene`

Файл: `agent-service/agent/tools/illustrate_scene.ts`.

Входная схема (zod):

| параметр | тип | обязательный | смысл |
|---|---|---|---|
| `sceneDescription` | string, max 500 | да | Описание сцены от DM: место, действие, атмосфера. На английском (указано в description тула), используется как caption и часть промпта. |
| `characters` | string[], max 6 | нет | Имена PC в кадре — для подмешивания их внешности из листов персонажей. |

Поведение:

- Кампания резолвится по auth звонящего (как в `advance_day`); явный
  `campaignId` не принимается — тул работает только в чате активной кампании.
- Нет кампании / кампания без `boundChat` → `{ ok: false, error: «Иллюстрации
  доступны только в рамках кампании» }`, без запросов к Runware.
- Любой сбой на этапах Runware/Telegram возвращает `{ ok: false, error }`
  (мягкая ошибка, не throw) — агент продолжает текстом.
- `execute` асинхронный; общий таймаут запроса к Runware — 30 секунд
  (`AbortSignal.timeout(30_000)`).

## Внешность персонажа

- `CharacterSheet.appearance?: string` в `agent/lib/campaigns/types.ts`.
- Сериализация в frontmatter листа персонажа
  (`store.ts`: `characterToFrontmatter` / парсер, ключ `appearance`).
- `save_character`: опциональный вход `appearance`
  («Внешность персонажа для иллюстраций: черты лица, волосы, одежда,
  приметы — на английском»).
- `NewCharacterInput` в `store.ts` расширяется тем же полем.
- Скилл `agent/skills/create-character/SKILL.md`: интервью обязано спросить
  краткое описание внешности и передать его в `save_character`.

Старые листы без `appearance` читаются как обычно (поле просто отсутствует);
в промпт такие персонажи не добавляют текста внешности.

## Сборка промпта

Детерминированная конкатенация (модуль `runware.ts` или тул):

```
positivePrompt = [
  sceneDescription,
  ...appearances (внешность каждого персонажа из `characters`,
                  найденного в листах кампании),
  `Setting: ${campaign.setting}`,
  `Theme: ${campaign.theme}`,
  "high fantasy, cinematic lighting, detailed illustration",
].filter(Boolean).join(", ")
```

`negativePrompt` — константа по умолчанию:
`"text, watermark, signature, blurry, low quality, deformed"`.

Сопоставление имён персонажей — case-insensitive по `name` листов кампании.
Неизвестное имя тихо игнорируется (в промпт не попадает, ошибкой не считается).

## Клиент Runware

Файл: `agent-service/agent/lib/runware.ts`.

- Чистый `fetch`, без SDK и WebSocket:
  `POST https://api.runware.ai/v1`, заголовок
  `Authorization: Bearer $RUNWARE_API_KEY`, тело — массив из одной задачи:

  ```json
  [{
    "taskType": "imageInference",
    "taskUUID": "<uuid v4>",
    "model": "$RUNWARE_MODEL",
    "positivePrompt": "...",
    "negativePrompt": "...",
    "width": $RUNWARE_WIDTH,
    "height": $RUNWARE_HEIGHT
  }]
  ```

- Ответ: `data[0].imageURL` (вложенность `data` уточняется по фактическому
  ответу API при реализации; оба варианта — верхний уровень и `data[]`).
- Таймаут 30 секунд через `AbortSignal.timeout`; не-2xx или отсутствие
  `imageURL` → throw с человекочитаемой причиной (ловится тулом).

### Конфигурация (env)

| переменная | дефолт | смысл |
|---|---|---|
| `RUNWARE_API_KEY` | — (обязательна) | API-ключ Runware |
| `RUNWARE_MODEL` | `runware:101@1` (SDXL 1.0) | идентификатор модели; точный id сверяется со списком моделей Runware при реализации |
| `RUNWARE_WIDTH` | `1024` | ширина картинки |
| `RUNWARE_HEIGHT` | `1024` | высота картинки |

При отсутствии `RUNWARE_API_KEY` тул сразу возвращает мягкую ошибку про
ненастроенную генерацию (без сетевых запросов). Переменные добавляются в
`agent-service/.env.example`.

## Доставка в Telegram

- Прямой вызов Bot API `sendPhoto` через `callTelegramApi` из
  `eve/channels/telegram` (уже используется в проекте):
  `{ chat_id, photo: imageURL, caption: sceneDescription, message_thread_id? }`.
- `chat_id` и `message_thread_id` берутся из `campaign.boundChat`.
- Caption обрезается до лимита Telegram (1024 символа).
- Telegram сам скачивает файл по URL; TTL URL Runware (7 дней) не критичен.
- Перед отправкой фото — `sendChatAction` с действием `upload_photo`
  (необязательно, падение игнорируется).

## Инструкции агенту

В `agent/instructions.md` добавляется короткий блок «Illustrations»:

- В начале значимой новой сцены внутри активной кампании вызови
  `illustrate_scene` с кратким описанием сцены на английском и именами
  персонажей в кадре.
- Не иллюстрируй каждый ответ: только новые локации, важные события,
  появление ключевых NPC.
- Вне кампании тул не работает — не вызывай его в личке без кампании.
- Если тул вернул ошибку — молча продолжай текстом, не упоминай сбой.

## Ошибки и крайние случаи

| случай | поведение |
|---|---|
| нет кампании / нет boundChat | мягкая ошибка тула, без запросов |
| нет `RUNWARE_API_KEY` | мягкая ошибка тула |
| Runware: не-2xx / нет imageURL / таймаут 30с | мягкая ошибка тула, фото не шлётся |
| Telegram sendPhoto упал | мягкая ошибка тула (URL возвращается агенту) |
| персонаж из `characters` не найден | тихо игнорируется |
| лист персонажа без `appearance` | персонаж в кадре, но без текста внешности |

Игра никогда не блокируется генерацией картинки.

## Тестирование

- Расширить `scripts/smoke-campaigns.ts`: round-trip поля `appearance`
  (сохранение → чтение листа персонажа).
- Юнит-проверка сборки промпта (чистая функция): описание + внешность +
  сеттинг; неизвестный персонаж игнорируется.
- Ручная e2e-проверка: сообщение в чат кампании → DM вызывает тул → фото
  приходит в чат с caption. Runware-запрос реальный, требует ключа.

## Вне рамок

- Автоматические иллюстрации на старте кампании / при `advance_day`.
- Сохранение картинок в папку кампании.
- LLM-генерация промпта отдельным вызовом.
- img2img, LoRA кампании, стилистические пресеты.
